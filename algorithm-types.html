Artifact Title

Machine Learning Algorithm Types: A Visual Framework

Introduction

Choosing the right algorithm starts with two questions: do I have labels, and what kind of data am I working with? This framework maps 12 widely used algorithms against those two questions so the right starting point is visible at a glance.

Description

An interactive infographic that classifies each algorithm by learning type and application domain, then explains how it works, where it is used in practice, and how it relates to the other algorithms in its family.

Objective

Identify and categorize key ML algorithms, illustrate their primary domains, give real-world use cases, and communicate why each one matters, including the generative models behind today's AI products.

Process

Selected 12 algorithms spanning classical ML through generative AI, researched each from primary sources, classified them on a learning-type by domain grid, grouped them into families, and built a selection guide.

Tools and Tech Used

Original research papers and scikit-learn documentation for content; HTML, CSS, and vanilla JavaScript for the interactive framework and filters; GitHub Pages for publishing.

Value Proposition of the Artifact

A one-page reference that shortens algorithm selection: start from the data type and label availability, then narrow to a family and a specific model with known trade-offs.

Unique Value

Every algorithm includes a use case from QA automation and data engineering alongside general industry examples, showing how the same models apply to test reliability, defect triage, and pipeline quality.

Relevance

Relevant for ML engineers, QA and data engineering leads, and technical reviewers who need to justify why a given model fits a problem before investing in it.

References

Original papers for Random Forests, Gradient Boosting, SVM, CNNs, GANs, Transformers, BERT, and Diffusion models, plus the scikit-learn User Guide. Full list below.

How the Classification Was Built

The framework is the result of four decisions: which axes to use, which categories to allow on each axis, how to sort each algorithm, and how to handle the cases that did not fit.

1. Choosing the Two Axes

I tested several ways to group the algorithms, including by family, by complexity, and by year introduced. None of them helped answer the practical question of which model to try first. Two factors did: whether labeled data exists, which decides the learning type, and what shape the data takes, which decides the domain. Together they narrow the choice to two or three candidates, so they became the rows and columns.

2. Defining the Categories

The learning-type axis started with the two categories the assignment names, supervised and unsupervised. BERT, GPT, and diffusion models did not fit either one: they need no human labels, yet they train on a prediction target. Their training method, where the target is hidden or corrupted data the model must restore, is self-supervised learning, so I added it as a third row. The domain axis uses four columns for the main kinds of input and output: tabular data, images, text, and new content.

3. Sorting Rules

Learning type was assigned by what the training signal is: human labels (supervised), no target at all (unsupervised), or a target created from the data itself (self-supervised). Domain was assigned by documented, common use rather than theoretical possibility. An algorithm appears in more than one column only when it is widely used there in practice. This is why SVM spans tabular, vision, and NLP while CNN stays in vision.

4. Resolving Edge Cases

BERT appears in two rows because its two training stages differ: self-supervised pre-training, then supervised fine-tuning. GAN stays unsupervised even though its discriminator is a classifier, because the "real or fake" labels are created inside the model and no human labels are needed. Diffusion is self-supervised because it learns by predicting the noise added to its own training images. Linear Regression and SVM share a family because both learn a weighted combination of features, even though one predicts numbers and the other classes.

5. Checking the Result

I cross-checked each placement against the original paper and the scikit-learn documentation, then made the framework grid, the profile badges, and the comparison matrix agree on every algorithm. Empty cells were kept on purpose. For example, there is no supervised generative model here, and no unsupervised NLP model. The gaps show where the current field concentrates.

6. What the Classification Reveals

Two patterns emerged. Classical algorithms (1-7) cluster in the supervised and unsupervised rows on tabular data. Deep learning algorithms (8-12) move toward the self-supervised row and toward unstructured data. The shift from human labels to self-generated labels is the change that made large generative models possible.

Algorithm Profiles

Each profile covers the four required dimensions: algorithm type, application domains, real-world use cases, and how it works. Use the filters to compare groups.

1. Linear Regression

Family: Linear models
SUPERVISED Tabular

How it works

Fits a straight line (or hyperplane) through the data by choosing weights that minimize the squared error between predicted and actual values. The output is a continuous number, and each weight shows how much a feature moves the prediction.

Use cases

  • House price and sales forecasting
  • Estimating demand from price and seasonality
  • QA: predicting regression-suite run time from the number of tests and changed modules

2. Decision Tree

Family: Tree-based models
SUPERVISED Tabular

How it works

Splits the data with a sequence of if/else questions on features (for example, "files changed > 20?"). At each step it picks the split that best separates the target, measured by Gini impurity or entropy. Leaves hold the final prediction.

Use cases

  • Loan approval and credit risk rules
  • Medical triage decision support
  • QA: explainable rules for routing defects to the right team

3. Random Forest

Family: Tree ensembles (bagging)
SUPERVISED Tabular

How it works

Trains hundreds of decision trees, each on a random sample of rows and features, then averages their votes. Because the trees make different mistakes, averaging them reduces overfitting and gives stable, accurate predictions.

Use cases

  • Credit card fraud detection
  • Customer churn prediction
  • QA: predicting which tests are likely to fail for a given code change

4. Gradient Boosting (XGBoost, LightGBM)

Family: Tree ensembles (boosting)
SUPERVISED Tabular

How it works

Builds small trees one after another. Each new tree is trained to correct the errors left by the trees before it, following the gradient of the loss function. The final model is the weighted sum of all trees, and it is often the most accurate choice for tabular data.

Use cases

  • Search ranking and ad click-through prediction
  • Insurance claim risk scoring
  • Data engineering: scoring ETL batches for data-quality risk before loading

5. Support Vector Machine (SVM)

Family: Margin-based classifiers
SUPERVISED Tabular NLP Computer Vision

How it works

Finds the boundary that separates classes with the widest possible margin. The "kernel trick" maps data into a higher-dimensional space so curved boundaries become straight lines. It works well on small or high-dimensional datasets.

Use cases

  • Spam filtering and text categorization (TF-IDF features)
  • Handwriting and face recognition on extracted features
  • QA: classifying bug reports as UI, API, or data issues

6. K-Means Clustering

Family: Clustering
UNSUPERVISED Tabular Computer Vision

How it works

Places K center points, assigns every data point to its nearest center, moves each center to the mean of its points, and repeats until the groups stop changing. No labels are needed. The algorithm discovers the groups on its own.

Use cases

  • Customer segmentation for marketing
  • Image color quantization and compression
  • QA: grouping thousands of failure logs into a handful of root-cause clusters

7. Principal Component Analysis (PCA)

Family: Dimensionality reduction
UNSUPERVISED Tabular Computer Vision

How it works

Finds new axes (principal components) that capture the most variance in the data, then projects the data onto the top few. Many correlated features are compressed into a small number of informative ones with minimal information loss.

Use cases

  • Visualizing high-dimensional data in 2D
  • Noise reduction and faster training before another model
  • Data engineering: spotting anomalous pipeline runs across dozens of metrics

8. Convolutional Neural Network (CNN)

Family: Deep learning (vision)
SUPERVISED Computer Vision

How it works

Slides small learned filters across an image to detect local patterns. Early layers find edges, middle layers find textures and shapes, and deep layers recognize whole objects. Pooling layers shrink the image so the network sees more context at each level.

Use cases

  • Medical image diagnosis (X-ray, MRI)
  • Object detection in self-driving cars
  • QA: visual regression testing that flags real UI layout breaks but ignores harmless rendering noise

9. Transformer Encoder (BERT)

Family: Transformers (encoder)
SELF-SUPERVISED + SUPERVISED FINE-TUNING NLP

How it works

Uses self-attention so every word looks at every other word in both directions. It is pre-trained by hiding random words and predicting them from context (masked language modeling). It is then fine-tuned on a smaller labeled dataset for the target task.

Use cases

  • Sentiment analysis of product reviews
  • Search query understanding and named-entity recognition
  • QA: detecting duplicate bug tickets by semantic similarity

10. Transformer Decoder / LLM (GPT)

Family: Transformers (decoder)
SELF-SUPERVISED NLP Generative AI

How it works

It is trained on huge amounts of text to predict the next token, using attention over all previous tokens. It generates text by repeatedly predicting and appending one token at a time. Instruction tuning and human feedback then align it with helpful behavior.

Use cases

  • Chat assistants, summarization, and code generation
  • Retrieval-augmented question answering over company documents
  • QA: generating test cases and test data from user stories

11. Generative Adversarial Network (GAN)

Family: Deep generative models
UNSUPERVISED Generative AI Computer Vision

How it works

Two networks compete. A generator turns random noise into fake samples, and a discriminator tries to tell fake from real. As each improves against the other, the generator learns to produce realistic data without any labels.

Use cases

  • Photo-realistic faces and image super-resolution
  • Synthetic medical images to augment small datasets
  • Data engineering: privacy-safe synthetic tabular test data (for example, CTGAN)

12. Diffusion Model (Stable Diffusion)

Family: Deep generative models
SELF-SUPERVISED Generative AI Computer Vision

How it works

During training, noise is added to images step by step, and a network learns to predict and remove that noise. To generate, it starts from pure noise and denoises it step by step into a new image. A text encoder steers each step toward the prompt.

Use cases

  • Text-to-image generation for design and marketing
  • Image inpainting, editing, and upscaling
  • QA: generating varied UI and document images to test OCR and vision pipelines

How the Algorithms Relate

The 12 algorithms fall into five families. Within each family, later models build directly on earlier ideas.

🌳 Tree-based Models

Decision Treemany trees, averaged Random Foresttrees fix each other's errors Gradient Boosting

One tree is easy to read but overfits. Bagging (Random Forest) and boosting (Gradient Boosting) trade some readability for much higher accuracy. These are the default first choice for tabular data.

📏 Linear and Margin-based Models

Linear Regressionboth linear; SVM adds margin + kernels SVM

Both learn weighted combinations of features. Linear Regression predicts numbers, while SVM separates classes and can bend its boundary with kernels. They are fast, simple baselines that are hard to beat on small data.

🔍 Unsupervised Structure Finders

PCAcompress, then group K-Means

PCA reduces the number of dimensions, and K-Means groups similar points. They are often chained: PCA first to remove noise, then K-Means to find segments.

🧠 Deep Learning for Perception and Language

CNNattention replaces convolution Transformerencoder / decoder BERT · GPT

CNNs learn features from pixels automatically. Transformers learn relationships between all parts of the input through attention. BERT keeps the encoder to understand text, while GPT keeps the decoder to generate it.

🎨 Generative Models

GANmore stable training Diffusionprompted by Transformer text encoder

GANs produced the first convincing synthetic images but are unstable to train. Diffusion models train more reliably and now power most text-to-image tools, guided by a language model's understanding of the prompt.

⚖️ The Big Divide

Classical MLvs Deep Learning

Algorithms 1-7 rely on structured features and stay interpretable and cheap. Algorithms 8-12 learn their own features from raw images and text, and need more data and compute. The data type usually decides which side a problem falls on.

Choosing an Algorithm: A Practical Guide

The framework becomes useful when it turns into a decision. Start with the question that matches your situation.

Labeled tabular data, and stakeholders need the "why"?

Start with a Decision Tree or Linear Regression. Move to Random Forest or Gradient Boosting if accuracy matters more.

Tabular data with no labels?

Use PCA to reduce noise, then K-Means to find natural groups or outliers.

Small dataset with many features?

SVM is a strong, inexpensive baseline for short text or extracted image features before reaching for deep learning.

Raw images or video?

A CNN, ideally a pre-trained one fine-tuned on your own images.

Need to understand or classify text?

A fine-tuned BERT-style encoder.

Need to create new content?

Text: a GPT-style LLM. Images: Diffusion. Synthetic tabular test data: a GAN.

💭 Professional Reflection

Building this framework changed how I think about algorithm selection. Before, I tended to think in terms of individual models. Laying them out on a learning-type-by-domain grid showed me that the choice is mostly determined by two factors: whether labels exist and what shape the data takes. Once those are known, the list of sensible candidates shrinks to two or three.

The hardest part was classification itself. The assignment asks for supervised or unsupervised models, but models like BERT, GPT, and diffusion do not fit cleanly into either category. Researching how they are trained led me to self-supervised learning, where the data provides its own labels. That idea explains why generative AI scaled so quickly: it removed the need for expensive human labeling.

Connecting each algorithm to my own work in QA automation and data engineering made the material concrete. Random Forest for test-failure prediction, K-Means for clustering failure logs, CNNs for visual regression, and LLMs for test-case generation are all problems I have faced or can apply directly. Matching model complexity to the problem, not to the hype, is the principle I will carry through the rest of this program and my engineering work.
