Artifact Title

Inside a Neural Network: A Visual Guide to Its Components

Introduction

A neural network is often presented as a black box. This presentation opens the box and shows the six components inside it, what each one does, and how they cooperate on every training step.

Description

A web-based slide deck with an architecture diagram, one slide per component, a training-loop slide that connects them, findings from hands-on experiments in the TensorFlow Neural Network Playground, and a summary slide.

Objective

Define and describe layers, neurons, weights, activation functions, loss functions, and optimization algorithms, illustrate how data flows through a network, and explain these ideas concisely for a mixed technical and non-technical audience.

Process

Trained models in the Neural Network Playground while varying datasets, noise, input features, layers, and learning rate. Researched each component from primary sources, grouped the components by role, drew the diagrams, and built the deck.

Tools and Tech Used

TensorFlow Neural Network Playground for experiments; original papers and the Deep Learning textbook for content; HTML, CSS, inline SVG, and vanilla JavaScript for the slides and diagrams; GitHub Pages for publishing.

Value Proposition of the Artifact

A short, visual explanation that lets a reviewer, manager, or new engineer understand what is happening inside a neural network in about ten minutes, without heavy mathematics.

Unique Value

One color per component is used consistently across every diagram, slide, and table. Each component is also mapped to a QA automation analogy, such as treating the loss function as a test assertion that measures the gap between expected and actual output.

Relevance

Where my previous artifact compared algorithms from the outside, this one explains how a deep learning model works from the inside. It underpins the CNN, BERT, GPT, and diffusion models covered elsewhere in this portfolio.

References

Component 1 · Layers04 / 12

Layers: The Network's Stages

A layer is a group of neurons that processes data at the same stage. Each layer passes its output to the next.

  • Input layer: receives the raw features, with one neuron per feature. It does no computation.
  • Hidden layers: transform the data step by step. Early layers learn simple patterns, and deeper layers combine them into complex ones.
  • Output layer: produces the prediction. It has one neuron for a number (regression) or one per class (classification).

Depth (number of hidden layers) is what puts the "deep" in deep learning. Specialized layer types include convolutional layers for images and attention layers for text.

QA analogy: layers work like stages in a CI pipeline. Each stage takes the previous stage's output, adds its own processing, and hands the result on.

Component 2 · Neurons05 / 12

Neurons: The Basic Unit of Computation

A neuron takes several inputs, weighs them, adds a bias, and passes the result through an activation function.

  • Step 1, weigh: multiply each input by its weight.
  • Step 2, sum: add the results and the bias.
  • Step 3, activate: pass the sum through the activation function to get the neuron's output.

A single neuron can only draw a straight boundary. Many neurons across several layers can draw almost any shape. The neuron is loosely inspired by biology, but it is pure arithmetic.

QA analogy: a neuron is like a weighted risk score for a release. Each signal (failed tests, code churn, open defects) counts by its importance, and the total decides go or no-go.

Component 3 · Weights06 / 12

Weights and Biases: Where the Learning Lives

A weight is a number on each connection that sets how strongly one neuron influences the next. A bias shifts a neuron's output up or down.

  • Large positive weight: the input strongly pushes the output up.
  • Negative weight: the input pushes the output down.
  • Weight near zero: the input is mostly ignored.
  • Bias: lets a neuron activate even when all inputs are zero, like the intercept of a line.

Weights start as small random values. If they all started equal, every neuron would learn the same thing. Training then adjusts them, one small step at a time, to reduce the loss.

Component 4 · Activation Functions07 / 12

Activation Functions: Adding the Curves

An activation function transforms a neuron's weighted sum. Without it, any number of layers would collapse into one straight-line model.

ReLU

max(0, z)

Default for hidden layers. Fast and avoids vanishing gradients for positive inputs.

Sigmoid

1 / (1 + e⁻ᶻ)

Squashes output to 0 to 1. Used for yes/no (binary) outputs.

Tanh

tanh(z)

Outputs −1 to 1, centered on zero. Common in older and recurrent networks.

Softmax

eᶻⁱ / Σ eᶻʲ

Turns output scores into class probabilities that sum to 1.

Why it matters: stacking linear layers still gives a linear model. The activation's bend is what lets a network separate circles, spirals, faces, and sentences.

Rule of thumb: ReLU in the hidden layers. For the output, sigmoid for binary classification, softmax for multi-class, and no activation (linear) for regression.

Softmax example: scores of 2.0, 1.0, and 0.1 become probabilities of 0.66, 0.24, and 0.10.

QA analogy: an activation is like a threshold rule on a metric. It decides how strongly a raw signal should pass on, instead of passing every value through unchanged.

Component 5 · Loss Functions08 / 12

Loss Functions: Measuring the Mistake

A loss function compares the prediction with the true answer and returns one number: how wrong the network is. Training exists to make that number smaller.

  • Mean Squared Error (MSE): the average of (prediction − truth)². Used for regression, such as predicting prices or run times.
  • Binary cross-entropy: used with a sigmoid output for yes/no tasks, such as pass or fail.
  • Categorical cross-entropy: used with a softmax output for multi-class tasks, such as labeling a defect as UI, API, or data.

The loss must match the task. The wrong loss can train a model that scores well on paper but optimizes the wrong goal.

QA analogy: the loss function is the test assertion. It compares expected and actual output, but instead of only pass or fail it reports how far off the result is.

Component 6 · Optimization Algorithms09 / 12

Optimizers: Walking Downhill

An optimizer uses the gradient of the loss to decide how to change each weight. The learning rate sets how big each step is.

Gradient Descent

Steps against the gradient using the whole dataset. Accurate but slow on large data.

SGD (mini-batch)

Updates after each small batch. Noisy but fast, and the noise can help escape poor solutions.

Momentum

Keeps a running direction, like a ball rolling downhill, to move faster and smooth out zigzags.

Adam

Combines momentum with a separate adaptive step size per weight. A strong default for most projects.

QA analogy: the optimizer is the fix-and-retest cycle. After each failed run it makes a small, targeted change in the direction that reduces failures, then runs again.

Summary12 / 12

Why Visualizing Neural Networks Matters

The importance of visualizing

  • It removes the black box. A diagram shows that a network is layers of simple, weighted sums, not magic.
  • It shows cause and effect. Watching the boundary change in the Playground connects each setting to a visible result.
  • It speeds up debugging. A plot of training and test loss reveals overfitting or a bad learning rate quickly.
  • It builds shared understanding. Managers and engineers can discuss the same picture, which makes design decisions easier to explain.

Key insights from this exercise

  • Only weights and biases are learned. Everything else is an engineering choice.
  • Activation functions make depth useful. Without them, ten layers act like one.
  • The loss defines success. The network gets very good at whatever the loss measures, so it must match the real goal.
  • The learning rate is the most sensitive setting. Too high diverges, too low stalls.
  • Start simple. Add layers and neurons only when the data's shape requires them.

Takeaway: a neural network learns by repeating one loop: predict, measure the error, trace it back, and adjust. Every component exists to make one step of that loop work.

How I Organized the Components

The order, grouping, and colors in the deck were deliberate choices. These are the reasons behind them.

1. Following the Data

The component slides follow the order in which a training example meets each component: it enters the layers, is processed by neurons through their weights and activation, is scored by the loss, and is corrected by the optimizer. Reading the deck in order mirrors one training step.

2. Grouping by Job

I sorted the six components into four groups, each answering one question: Structure (where the data goes), Parameters (what is learned), Transformation (how curves are captured), and Learning (how the network improves). Grouping by job shows that the components are not a flat list but parts with distinct roles.

3. Learned vs Chosen

The most useful split I found is between what the network learns and what the engineer decides. Only weights and biases change during training. Making this explicit clarifies what "training a model" actually changes, and where an engineer's design decisions have their effect.

4. Resolving Edge Cases

Biases are grouped with weights because both are learned parameters, even though a bias is not a connection. The activation is part of every neuron but gets its own slide, because it is chosen separately and is what makes depth useful. Backpropagation is shown in the training loop rather than as a component, because it calculates gradients for the optimizer instead of being a part of the network.

5. One Color per Component

Each component keeps the same color on the architecture diagram, its slide, the training loop, and the reference table. A reader who learns that teal means "weights" on slide 2 can recognize weights everywhere else without re-reading labels.

6. Theory Checked by Experiment

Each claim on the component slides was tested in the Neural Network Playground before it went into the deck. For example, the claim that activation functions supply non-linearity was confirmed by switching to a linear activation and watching the circle dataset become unsolvable.

💭 Professional Reflection

Before this assignment, I understood neural networks mostly as a sequence of terms: layers, weights, backpropagation. Training models in the Neural Network Playground turned those terms into behavior I could see. Switching the activation to Linear and watching the circle dataset become unsolvable showed me, more clearly than any definition, that activation functions are what make depth useful.

The main challenge was deciding how to present six components that only make sense together. Explaining them one at a time risked a disconnected list, but explaining them all at once was overwhelming. My strategy was to anchor everything to one architecture diagram, give each component a single color that carries through every slide, and close with a training-loop slide that shows all six working in one step. Sorting them into components that are learned (weights and biases) and components that are chosen (everything else) was the insight that made the structure click.

The exercise also connected to earlier Model Development concepts. The Playground's noise experiment showed overfitting directly: training loss kept falling while test loss rose, and L2 regularization brought the two back together. The learning-rate experiments made the role of gradient descent concrete, and they explained why adaptive optimizers like Adam are the common default.

In my QA automation work, I can now reason about a model the same way I reason about a test framework: the loss function is the assertion, and the optimizer is the fix-and-retest cycle. That framing will help me evaluate AI-based testing tools critically and explain their behavior to teammates. The principle I take away is to start with the simplest network that fits the data's shape, and add complexity only when the experiments show it is needed.
